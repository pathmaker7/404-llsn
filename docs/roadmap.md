# Roadmap: Lunar Landing Site Navigator

Team 404 agents, NASA Space Apps Challenge 2026, Naryn. This file is the single list of what the tool does, why it is built that way, what is being added, and what is deliberately left out. Status is updated as each item lands; every number quoted here comes from a command listed in README "Verification".

Status keys: **done** (shipped and checked), **building** (in progress), **planned**, **out** (deliberately not done, reason given).

## 1. The challenge in one paragraph

Source: https://www.spaceappschallenge.org/2026/challenges/lunar-landing-site-navigator/

> "Your challenge is to create an intuitive tool or application that lets mission planners, educators, and the public compare landing sites and dates quickly, visualizing Sun and Earth positions relative to the horizon to assess power generation potential and direct-to-Earth communication windows."

The statement names the existing tools and the gap: "Tools that provide this information, such as NASA's Quickmap, Moon Trek, and the JPL Horizons System, are built for detailed analysis and are often difficult for non-specialists to use effectively for rapid scenario comparison." Our answer: one offline page that turns NASA terrain plus ephemeris into "which site, which date" in seconds.

The Naryn info session lists the same challenge as "CLPS mission explorer: choosing landing sites on the Moon; web map of landing zones with filters for slope and light". Slope is therefore an expected feature locally.

## 2. Architecture (what exists today)

```
app/index.html          one static page, classic <script> tags, opens from file://, no server, no build
 ├ vendor/astronomy.browser.min.js   astronomy-engine 2.1.19 (MIT): Sun, Earth, Moon ephemeris
 ├ data/dem.js          LOLA LDEM_75S_240M, 2x2 averaged to 480 m, cropped at 80 S, int16 base64 (4.3 MB)
 ├ data/sites.js        preset sites, generated by tools/build-sites.cjs
 ├ sky.js               Sun/Earth vectors rotated into the Moon body-fixed frame; az/el at a site
 ├ data/global.js       LOLA LDEM_4 whole Moon + 17 LDEM_64 boxes (474 m) around landing sites + site catalogue (9.7 MB)
 ├ terrain.js           polar DEM lookup, slope, the shared 360 degree horizon march (falls back to global past 80 S)
 ├ globe.js             whole-Moon heights, slope and horizon (patch near field + global far field)
 ├ analysis.js          disk fraction, lit/comm flags, runs, prefix sums, metrics, score, planner curve
 └ app.js               UI: map, date planner, comparison table, sky panorama, timeline, CSV
tools/
 ├ build-dem.cjs        IMG -> data/dem.js
 ├ build-sites.cjs      gazetteer centres -> best-lit rim points (about 4 minutes)
 ├ build-global.cjs     LDEM_4 + LDEM_64 boxes by HTTP range -> data/global.js (about 7 minutes)
 ├ test.cjs             npm test: maths and map orientation self-checks
 ├ validate-horizons.cjs npm run validate: our Sun/Earth az/el vs NASA JPL Horizons API
 └ smoke.cjs            npm run smoke: headless Chrome loads the page, no errors, screenshots
```

### 2.1 Pipeline and the reason for each choice

| Step | What it does | Why this and not the obvious alternative |
|---|---|---|
| Terrain | LOLA south polar DEM, 240 m averaged to 480 m, cropped at 80 S | Full 240 m polar file is 29 MB; 480 m keeps the page at 4.3 MB and still resolves crater rims. The pole is where the challenge says the problem is "particularly acute". |
| Horizon | For each whole degree of azimuth, march a great circle across the DEM and keep the highest elevation angle; Moon curvature included (`terrain.js#horizon`) | A flat-ground horizon is wrong at the pole: the Sun sits 0 to 2 degrees up, so a 1 degree ridge decides day or night. The statement asks for "the edge of the lunar sphere as seen from the landing site": the curvature term `rq * cos(t) - r0` does that. |
| No refraction | Elevation is pure geometry | The Moon has no atmosphere (statement: "Consider how to handle the Moon's lack of atmosphere"). |
| Ephemeris | astronomy-engine geocentric Moon and Sun, then the IAU WGCCRE lunar rotation (`sky.js#toMoonFixed`) | Runs offline in the browser for any date. Calling JPL Horizons live would need the internet and one request per site and date. Horizons is used instead as the referee (`npm run validate`). |
| Libration | Comes for free: Earth is placed with the true Moon orientation each hour | Earth wobbles about 7 degrees in the sky of the pole; that wobble is why Earth disappears for about two weeks at a time. |
| Power | Fraction of the solar disk above the skyline (`analysis.js#diskFraction`), "lit" when half or more is up | The Sun is 0.53 degrees wide and grazes ridges at the pole; a centre-only test flips on and off. |
| Comms | Earth centre above the skyline plus a margin (default 0.5 degrees) | Direct-to-Earth only, as the statement defines it; the margin covers antenna beam and DEM error. |
| Metrics | Prefix sums over the hourly flags give sunlit %, Earth %, both %, longest night, longest blackout, comm windows for any window in O(1) | The date planner needs these for every possible landing hour of the year (about 4,400 starts). |
| Score | `0.4 * sun% + 0.4 * earth% + 20 * (1 - longest night / stay)` | One sortable number. Power and comms weigh equally; the night term rewards short battery gaps. Weights are a choice, not physics, and the table shows the raw numbers next to it. |
| Presets | Crater centres from the USGS Gazetteer; the best-lit DEM pixel on the ring 0.85 to 1.15 crater radii out | Not typed in by hand, so every preset is reproducible and honest about where it came from. |

### 2.2 Evidence that it is right

| Check | Command | What would make it fail |
|---|---|---|
| Sun and Earth az/el vs JPL Horizons, 3 polar sites, 30 days | `npm run validate` | Any error above 0.1 degrees; proven with `SKY_BIAS_DEG=0.2`, which fails |
| Disk fraction, run detection, map not mirrored, Shackleton floor horizon about 22 degrees | `npm test` | A flipped projection, a wrong disk formula, a broken horizon march |
| Page loads offline, no console errors, map click adds a site | `npm run smoke` | Any runtime error |

## 4. Build plan

Every item ships with one check that is first shown to fail, then pass. All of 4.1 to 4.10 done on 2026-11-13; 4.8 waits only for a native speaker's review. Added: 4.11 NASA Artemis III checks.

### 4.1 Global coverage (owner decision 2026-11-13: whole Moon, full detail)

Constraint: the global LOLA map at 474 m (LDEM_64) is 530,841,600 bytes. An offline double-click page cannot load it, so detail is placed where it matters:

| Layer | Source | Resolution | Size in app | Used for |
|---|---|---|---|---|
| South pole | LDEM_75S_240M (existing) | 480 m | 4.3 MB | everything south of 80 S |
| Global base | LDEM_4 | 7.58 km | about 2.8 MB | the whole-Moon map, far-field horizon, custom points anywhere |
| Near field per curated site | LDEM_64, only the box around each site, fetched with HTTP range requests (PDS answers `accept-ranges: bytes`) | 474 m | 0.3 to 1.6 MB per site (the box widens toward the poles); global + 17 patches = 9.73 MB, app data 14.0 MB in total | horizon within about 75 km of each curated site |

Status 2026-11-13: **done**. Checks: global map correlates with the polar map and a mirrored one does not; the IM-1 patch matches the polar map to a median 4.5 m and a 3 px shift fails; Apollo 11 horizon 0.97 degrees, Apollo 15 13.3 degrees (Apennine front); JPL Horizons agrees at Apollo 11 and Chang'e 4 to 0.005 degrees.

Horizon at a point = the higher of the near-field march and the far-field march, per azimuth. It keeps the mast height control live because terrain ships, not frozen horizons.

Custom points outside a near-field patch use the 7.58 km global base and are labelled "coarse terrain". Reason: shipping 474 m everywhere is 530 MB.

Check: Apollo 11 horizon is under 2 degrees in every direction (flat mare); a point inside Shackleton from the global path agrees with the polar path within a stated tolerance; sources cited per site.

### 4.2 Sunset/Earthset countdown and solar elevation

From the existing hourly track: scan forward from "now" to the first sample where `lit` (or `comm`) flips. Show time remaining and the next rise; add "Sun el (mean / max)" and "next sunset after landing" to the table.

Check: a synthetic track with a known flip index returns that index; a never-setting track returns "none in span".

### 4.3 Slope (landability)

Slope from the DEM by central differences over the 480 m grid; overlay on the map (red above 10 degrees); slope per site in the table with a warning above 10 degrees. UI states that slope at 480 m is smoother than slope at lander scale (a few metres).

Check: a crater wall pixel on Shackleton is above 10 degrees; a known flat point is below.

### 4.4 Cross-check sunlight against published results

Compare our year-average sunlit % at three or more points with published LOLA illumination results (NASA PGDA polar illumination products, Mazarico et al. 2011, Icarus). Investigate any gap over about 5 percentage points before showing it. Table goes in README.

Status: **done** (`npm run crosscheck`). Source: PGDA product 69, AVGVISIB_75S_120M_201608 Sun and Earth maps. 131 points, 18.6 years, same definitions: median difference 0.3 pp Sun, 0.2 pp Earth; rotating our sampling 180° fails (14.9, 22.8 pp). The over-5-point gaps at ridge presets were investigated: NASA's best pixel within 240 m matches ours (Shackleton rim 85.8 vs 90.2), the 4 x 4 block mean does not, because the crest is one or two 120 m pixels wide. Nobile rim stays an outlier (+10.6 within 240 m, +1.6 within 480 m).

### 4.5 "Why small changes matter" neighbourhood map

Status: **done**. For the focused site, sunlit % and Earth % over the whole span for an 11 x 11 grid one terrain pixel apart (480 m, about 2.4 km each side), same pipeline as a site row; smoke checks the centre equals the site. 1.1 s in the browser after capping horizon marches at 300 km (results identical).

### 4.6 Live shadow map (stretch)

Status: **done**. One ray toward the Sun per 3 x 3 pixel cell (1.44 km), cached per time step, about 0.2 s per new time; follows the scrubber and play. `npm test` checks the ray method agrees with the horizon-profile method (561 of 561 site-times agreed when built).

### 4.7 Shareable link

Sites, span, stay, mast, margin and landing index in the URL hash; opening the link restores the view. Status: **done**. Names are cleaned once in addSite (markup, quotes, leading formula signs removed); a broken link falls back to defaults; language is in the link too.

### 4.8 Interface in Russian and Kyrgyz

Status: **built, review pending**. app/i18n.js holds 111 strings in three languages; `npm test` checks keys and placeholders match. Russian and Kyrgyz show as "draft" in the menu and a note until a native speaker approves them in docs/translations-review.md (`npm run i18n:review`) and sets REVIEWED to true.

### 4.9 Phone and projector

Status: **done**. Smoke fails if the page scrolls sideways at 390 px or 1920 x 1080; wide tables scroll inside their card; type grows on screens 1800 px and wider; map labels scale to the screen and avoid each other.

### 4.11 NASA Artemis III checks

Status: **done**. Source: NASA Artemis overview for Space Apps (NTRS 20250009323), "Key Artemis III Landing Requirements". Five of six are site properties: within 6° of the pole, landing slope under 10° (100 m), EVA slope within 2 km under 20°, direct-to-Earth communication with no relay, lighting. The table scores each site x/5 and names what fails. Example: Shackleton rim 4/5, the crater wall within 2 km is 33.7°. The sixth (land within 100 m of a target) is navigation.

## 5. Deliberately out

| Idea | Why not |
|---|---|
| Relay satellites (Lunar Pathfinder, Queqiao) | The statement scopes communication to "direct communication ... without relay satellites"; a relay model needs orbits we cannot validate in two days |
| DSN station availability on Earth | One of the three DSN complexes sees the Moon almost all the time; second-order next to terrain blocking |
| Thermal model | Statement mentions thermal only as a consequence of Sun position; a real model needs material properties |
| Lander shadow, boulders | Below DEM resolution |
| Full 474 m globally | 530 MB; see 4.1 |
| Live JPL Horizons calls in the app | Breaks offline use; used as the referee instead |
